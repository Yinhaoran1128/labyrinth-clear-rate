# 按实际完成战斗场数运行实施计划

> 使用 writing-plans、test-driven-development、executing-plans 和 verification-before-completion。按用户明确要求在当前工作树直接执行，不提交、不推送、不另设审批。

**目标：** 计算器仅使用内置 Rust/WASM，一次任务完成 N 场，保留战斗与推荐规则并提供后续区间估计所需统计量。

**架构：** Rust 事件循环增加可选 labyrinthTrials，局末累计、回调进度并判断停止；比较工具显式保留旧时间模式。Worker 初始化一次数据、一次 WASM 调用；取消终止 Worker。耗时以秒累计 Kahan 和 Welford 统计。

**约束：** 保留每局事件顺序、120 秒超时的原事件检查行为、固定半冷却、升级、怒气修正、持续 RNG。按用户后续要求，同归于尽只算成功，胜率分母统一为真实完成场数。保留原脚本与独立双引擎工具需要的共享资源。

## 重点风险

同归于尽不得从原始死亡日志重复推导失败；局末继续执行的触发器不能向下一局泄漏；全局时间与局部时钟偏移不可改变冷却；进度须在 WASM 同步运行时由导入函数主动发送；取消须可在主线程立即终止长任务。
