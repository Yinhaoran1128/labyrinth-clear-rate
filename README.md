# 迷宫胜率计算器

银河奶牛（Milky Way Idle）的迷宫计算与等级推荐用户脚本。基于原版 1.5.14，提供 Rust/WASM 战斗引擎、累进采样与单调回归推荐，以及战斗、生产房间的胜率或耗时—等级图。

当前计算器版本：**1.8.1**。包含安装脚本、构建源码、Rust 引擎源码和回归测试。

## 安装

先安装 Tampermonkey 或 Violentmonkey，再通过脚本管理器导入[内置版安装文件](labyrinth-clear-rate-rust-embedded.user.js)：

| 版本 | 安装文件 | 适用情况 |
|---|---|---|
| Rust 内置修正版（推荐） | [labyrinth-clear-rate-rust-embedded.user.js](labyrinth-clear-rate-rust-embedded.user.js) | 希望沿用原版迷宫规则；战斗引擎包含在脚本中 |

安装后停用原版计算器，刷新游戏页面。每次只启用一个计算器。生成版本已移除原版的自动更新地址，升级时重新导入对应文件。

“内置”指战斗引擎；游戏和脚本的 LZString 依赖仍需网络。计算在浏览器本地进行，详见[计算器说明](calculator/README.md)。

## 使用

1. 在游戏中设置各房间的迷宫配装及茶箱、咖啡箱、食物箱。
2. 点击“计算迷宫”，查看格子上的通关率和预计通关耗时。
3. 在自动化表格中设置目标胜率（默认 **70%**），点击“按胜率推荐”；或设置目标耗时（默认 **300 秒**），点击“按耗时推荐”。面板按计算、胜率、耗时分行排列。
4. 点击带 **▥** 的推荐等级打开对应图表；键盘聚焦单元格后也可按回车或空格。

表格显示的是可填写到“跳过如果高出等级”的**等级差 +1**，图表顶部显示实际房间等级。配装或升级改变后，重新计算推荐以更新图表。

图表默认聚焦目标附近，支持滚轮缩放、拖动平移、查看全部范围和点击记录定位。黄色横线表示本次目标胜率或目标耗时，竖线标记推荐等级。Esc、关闭按钮或点击遮罩可关闭图表；桌面和手机均可使用。

## 战斗房间

战斗推荐分阶段补足到累计 **300 → 1000 → 3000** 场，依次新增 300、700、2000 场。在候选等级附近增加样本并重新拟合，最终入选等级至少完成 3000 场。按等级和战斗配置缓存累计样本，胜率/耗时推荐及重复推荐共享，只补缺额；刷新页面后清空。各批使用不同且可复现的种子，复用 Worker/WASM 独立运行并合并稳定统计量。取消或失败的批次丢弃，已成功提交的样本保留。

缓存属于当前页面的内存，不写入本地持久存储。改变目标胜率或目标耗时可复用相同配置的样本；配装、等级、怪物或战斗增益变化后使用对应配置的独立样本。已有 3000 场时，后续粗搜索也直接使用这 3000 场，不重新抽取 300 场。普通计算使用单独的固定场数缓存，不混入推荐样本。

普通计算输入 N，每个战斗房间按 N 场计算；实际运行时 Rust 事件循环恰好完成 N 场。推荐的每批调用则只完成缺少的场数，进度显示已有场数加本批完成场数 / 累计目标，例如第二阶段从 **300/1000** 开始。取消立即终止 Worker，当前未提交批次不计入累计结果。

成功、死亡、超时各算一场。每局恢复满血满蓝、清临时状态、重置冷却，无额外刷新或复活等待；同一批次内随机序列持续推进，推荐的新批次使用新种子。同归于尽只计成功，不计死亡失败；胜率为成功场数 / 实际完成场数。

每局严格 120 秒截止：时间戳不超过本局开始后 120 秒的事件按原队列顺序执行，恰好 120 秒击杀有效；不执行更晚事件，届时仍未分胜负则记为耗时 120 秒的超时。

预计通关时间 = 全部已完成对局的耗时 ÷ 成功通关次数。计入最后一次成功之后的失败对局，第 N 场完整结束后立即停止，无未完成尾局；成功次数为零时显示 ∞。格子、自动化表格、耗时推荐和图表使用同一口径。

- 使用加权单调回归（PAVA），约束拟合胜率随房间等级不升高。
- 在搜索范围内寻找拟合胜率最接近目标的已模拟等级，允许低于目标；偏差相同时选更高等级。
- 耗时推荐对包含失败场次的预计通关耗时做加权单调拟合，约束耗时随等级不降低。选择拟合耗时最接近目标的等级，允许略超目标，等距时取更高等级；零通关样本保留为 ∞。
- 图表和记录表每级仅显示累计场数最多的最新结果，拟合、进度、缓存和调试场数均使用累计口径。
- 紫、蓝、粉红色分别对应累计 300、1000、3000 场；可通过图例筛选累计场数。部分等级复核后，图例可能只剩实际存在的档位。青色曲线表示最终单调拟合。
- 误差棒表示累计原始胜率的 **95% Wilson 二项置信区间**，按累计完成场数计算。战斗按独立试验近似，区间不是拟合曲线的置信带。
- 耗时模式显示原始耗时、拟合耗时和近似 95% 耗时区间（混合胜负使用 Fieller，全胜使用保守联合界）；区间同时使用耗时方差及耗时与成功的协方差，不是拟合曲线的置信带。零成功无法估计，稀少成功时上界可能为 ∞。

## 生产房间

普通生产和强化房间直接使用原概率公式计算，不需要随机模拟或单调拟合。

- 逐级计算整个推荐范围：有效技能等级向下取整后 **−300～+300**，最低房间等级为 1。
- 保留原生产推荐算法；图表展示每个整数等级的公式胜率，以及取整带来的阶梯变化。
- 生产耗时推荐逐级比较公式预计耗时，选择最接近目标的等级；图表展示耗时曲线，不对确定性的公式结果做随机样本拟合。
- 点选等级可查看操作成功率、双倍进度率、120 秒内操作次数、单次成功进度和所需进度单位。
- 强化房间显示目标强化等级，计算在时间内首次达到 **+5** 的概率。
- 完整等级表保留全部计算结果。生产图不显示模拟预算或采样置信区间。

## 项目结构

```text
.
├── labyrinth-clear-rate-rust-embedded.user.js  # 内置版安装文件
├── labyrinth-clear-rate.user.js               # 未修改的原版 1.5.14 基准
├── labyrinth-engine-comparison.user.js        # 双引擎对比工具
├── calculator/                               # 计算器适配、累进采样、推荐、图表及测试
├── comparison/                               # 引擎对比、构建依赖及回归测试
│   ├── engine/                               # Rust 引擎源码
│   ├── assets/                               # 已编译的内置 WASM
│   └── vendor/                               # 固定的第三方引擎快照
└── docs/images/                              # 图表示例
```

安装只需要内置版计算器 `.user.js` 文件。`calculator/` 和 `comparison/` 用于开发；[双引擎对比工具](comparison/README.md)可用于检查相同输入下的规则、胜率及耗时差异。

## 开发与验证

以下命令从本 README 所在的 `labyrinth-clear-rate/` 目录开始执行。需要 **Node.js 20 或更高版本**和 npm；现有回归使用 Node.js 23。已编译 WASM 随仓库提供，构建用户脚本不需要安装 Rust。

```sh
cd comparison
npm ci

# 构建唯一的内置版计算器安装文件
node ../calculator/build.mjs

# 运行计算器和引擎的 Node 回归测试
npm test

# 运行计算器真实浏览器回归
node ../calculator/tests/browser.mjs
```

浏览器测试使用隔离的 Chrome 会话、本地页面和合成角色数据。当前测试脚本的 Chrome 路径为 macOS 的 `/Applications/Google Chrome.app/Contents/MacOS/Google Chrome`；其他系统需要调整测试文件中的 `executablePath`。截图和测试 JSON 写入 `comparison/tests/browser-results/`，不纳入版本管理。

累进采样回归覆盖 300/700/2000 新增场数、配置缓存与复现种子、稳定方差/协方差合并、累计置信区间、失败/取消后补样、并发防重计，以及图表每级单条记录。浏览器回归还会通过真实 Worker/WASM 逐批重放种子，核对累计统计及取消后的样本保留。

开发时修改 `calculator/` 源码，再运行构建器更新内置版安装文件。不要仅编辑生成的 `.user.js`，否则下次构建会覆盖改动。构建器检查原版基准文件的 SHA-256，防止在未复核兼容性的情况下更换原版。

双引擎对比工具的构建与浏览器测试，在上述 `comparison/` 目录执行：

```sh
npm run build
npm run test:browser
```

修改 Rust 引擎后需重新编译 WASM、替换 `comparison/assets/mwi_engine.wasm`，再构建安装文件。具体命令和统计口径见[引擎开发说明](comparison/README.md#开发和验证)。
