# 迷宫胜率计算器 Rust 版 1.6.4

这是原版 1.5.14 计算器的两个独立版本，保留迷宫格子胜率/预计通关耗时、房间配装、模拟次数、生活房间计算、日志、胜率分布及自动化等级推荐功能。双引擎对比脚本另行保留。

| 文件 | 战斗引擎 | 规则 | 加载方式 |
|---|---|---|---|
| `../labyrinth-clear-rate-rust-embedded.user.js` | 本地适配后的 Rust/WASM | 匹配原版 1.5.14：迷宫升级、固定半冷却、怒气未命中减半、原统计口径 | 引擎已内置，计算时不下载战斗引擎 |
| `../labyrinth-clear-rate-rust-remote.user.js` | wow121 站点上游 Rust/WASM | 保留上游怒气增益候选与怪物随机初始冷却，结果允许不同 | 首次战斗计算时下载远程 WASM，同页后续计算复用 |

## 安装

1. 在 Tampermonkey 中导入需要的 `.user.js` 文件。
2. 停用原版计算器及另一个 Rust 版本，每次只启用一个计算器。双引擎对比测试脚本可单独使用。
3. 刷新游戏，使用原有「计算迷宫」按钮。按钮旁会标明当前 Rust 版本，悬停可查看规则说明。

两个新脚本均移除了原 GreasyFork 的 `@updateURL` / `@downloadURL`，避免被原版覆盖。保留原设置与配装；共享原面板防重复运行标志。

内置版仍使用原版的 LZString `@require` 读取压缩客户端数据；「内置」指战斗引擎，不承诺完全离线使用游戏或油猴依赖。

## 远程引擎

直接下载：<https://wow121.github.io/mwi-fastsim/engine/mwi_engine.wasm>。

适配与 Worker 调度代码留在脚本中，Rust 战斗代码来自上述 WASM，不需要自行发布远程文件或运行服务器。刷新页面后首次战斗计算重新检查远程资源（`cache: no-cache`）；不在每场战斗重新下载。下载、计算始终在用户浏览器执行，不将角色配装上传到引擎站点。

当前上游文件缺少已完成场次/超时统计。适配层用同一随机种子回放连续战斗，在怪物出生时间处向前回溯，恢复完整对局数和已完成耗时；最后未完成的一局排除。不会通过重复启动独立战斗更改上游的连续战斗规则，也不会将死亡/超时漏算。

当成功战斗的累计存活时间覆盖整个已完成区间时，可证明没有失败房间，直接使用胜利计数，避免为大量快速通关逐场重放。其余样本仍有额外统计耗时，模拟次数较大时可能明显增加。回溯超过 10000 次或单个请求超过 180 秒时会报错，可降低模拟次数；不能将界面的 2000 次上限理解为所有配装都能在时限内完成。若上游以后直接提供完整统计，则无需回溯。下载超过 30 秒、HTTP 错误或 WASM 接口变化都会明确报错，不自动切换内置版或原 JS 引擎。

当前上游仍未包含内置版的 Fury 修正，故怒气枪配装等结果可能与原计算器不同。原升级等级在 JS 适配层转换为永久增益，两版都会应用；远程版不会启用内置版专用的固定冷却或 Fury 覆盖选项。

## 数据与统计

角色输入仍由原版 DTO 构造器产生。内置版的共同基础表来自原引擎固定快照，当前客户端提供辅助数据；远程版使用当前客户端表，缺失的辅助表由随脚本提供的公开数据补齐。

胜率和预计通关耗时保留原统计口径：次数是 `120 秒 × 次数` 的模拟时间预算，实际完成对局数可能不同；预计通关耗时使用原版的最后一次成功时间/成功数。随机模拟独立运行仍会波动。内置版没有上游完整对局的最短/最长耗时字段，因此不再输出原调试文本中的 `0–0 秒` 区间；胜率和预计耗时不受影响。

调试结果 `combatMeta.firstRunDebug` 包含引擎模式、实际 WASM SHA-256、随机种子、计算耗时、场次数和远程统计回放次数，便于追查来源。引擎重置时清空战斗结果缓存。

## 战斗自动化等级推荐

两版 Rust 计算器的战斗推荐使用加权单调回归（PAVA），在同一怪物、配装和增益条件下约束拟合胜率随房间等级不升高。每个等级按引擎返回的实际统计次数 `combatMeta.trials` 加权，而不是按输入的模拟时间预算加权。该拟合用于抑制抽样波动，不代表置信区间，也不能保证真实战斗曲线严格单调。

目标默认 70%，仍可在界面修改。先在基准等级差 −300～+300 内向外探测，再根据拟合曲线插值寻找目标附近的整数等级。选择未四舍五入的拟合胜率最接近目标的已模拟等级，允许低于目标；偏差相同时选更高等级。长平台采用受限插值，避免逐级扫描。生活房间仍使用原推荐算法。

粗搜索使用 30 的模拟预算，在候选及其附近 ±2 级分阶段提高到 100、300、1000，并在每轮拟合后重新定位，避免被粗采样的错误边界锁定。最终入选等级经过 1000 预算的模拟。这里的预算仍表示 `120 秒 × 预算` 的连续战斗时间，而非严格的对局数；更长的运行替换较短的结果，不重复累加重放样本。推荐的复核不复用旧战斗缓存，因此计算会比原来的 30 预算搜索更久，随机运行仍可能波动。

表格仍显示可填写到“跳过如果高出等级”的等级差 +1。悬停推荐结果会分别显示拟合胜率和该等级的原始模拟胜率。普通“计算胜率”仍显示原始模拟结果，拟合不修改引擎输出或战斗规则。

## 胜率—等级图

完成战斗等级推荐后，点击带 `▥` 图标的推荐设置等级打开对应怪物的图表，也可聚焦该单元格后按回车或空格。图表保存本轮推荐搜索中每一次成功完成的模拟调用，包括同一等级后来被 100、300、1000 预算复核替换的短运行；不会把较短运行重复加入最终拟合。刷新页面或重新计算会以新的推荐结果替换旧记录。

- 紫色、蓝色、绿色、粉红色散点分别表示 30、100、300、1000 预算，误差棒显示该轮原始胜率的 95% Wilson 二项置信区间。旧轮次略淡，每个等级的最新结果参与单调拟合；青色折线连接最终拟合值，不做可能破坏单调性的平滑处理。
- 黄色横线表示目标胜率，竖线标记推荐房间等级。顶部显示推荐等级、拟合胜率、原始模拟胜率和原始胜率的区间。
- 默认展示推荐等级附近的目标区域。可滚轮缩放、拖动平移或点击图例筛选预算；“全部范围”展示完整横轴范围，“目标附近”回到默认视图。
- 悬停或点击散点、使用键盘聚焦散点可查看成功数/实际统计次数、预算、轮次和区间。“全部模拟记录”表保留每轮结果，点击行可定位对应散点。Esc、关闭按钮或点击遮罩关闭图表，焦点返回推荐单元格；桌面和窄屏均支持。

区间采用 `p = successes / combatMeta.trials` 和实际 `n = combatMeta.trials`，而非输入预算；使用 `z = 1.959963984540054` 的双侧 95% Wilson score 公式。0% 或 100% 样本不会得到零宽区间。公式来源：[NIST 比例置信区间](https://www.itl.nist.gov/div898/handbook/prc/section2/prc241.htm)。连续战斗的依赖性和原统计口径仍按独立二项试验近似，因此图中区间不保证覆盖率，也不是拟合曲线的置信带。

### 生产房间图表

普通生产和强化房间也可点击推荐等级打开图表。推荐计算完成时，用相同角色、配装、茶箱和迷宫升级参数，逐级计算整个推荐搜索范围（有效技能等级向下取整后 −300～+300，房间等级最低为 1）。生产推荐仍按原算法选取；绘图不会修改推荐结果。

- 青色曲线和点展示原公式计算的通关概率，点对应整数等级，连线仅用于辅助阅读。没有随机模拟、单调拟合或采样置信区间。
- 默认聚焦推荐等级附近，支持全部范围、缩放、拖动和完整等级表。顶部显示推荐等级、计算胜率、每次操作成功率和操作次数。
- 点选等级可查看操作成功率、双倍进度率、120 秒内操作次数，以及普通生产的单次成功进度和所需进度单位；强化房间显示目标强化等级。
- 普通生产按每次操作获得 0、1、2 进度单位的概率动态规划计算；强化按失败退一级、成功升一级或两级、首次达到 +5 的概率动态规划计算。阶梯变化保留原值，不做平滑或拟合。
- 全部等级数据来自本轮推荐时的状态快照；改换配装或升级后，需要重新计算推荐来更新图表。
