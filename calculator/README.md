# 迷宫胜率计算器 Rust 内置版 1.8.1

基于原版 1.5.14 的配装与界面，战斗统一使用内置 Rust/WASM。保留普通计算、生活/强化房间、自动化推荐、表格及图表。

## 安装与运行

1. 在 Tampermonkey 中导入 [`../labyrinth-clear-rate-rust-embedded.user.js`](../labyrinth-clear-rate-rust-embedded.user.js)。
2. 停用原版计算器，刷新游戏；每次只启用一个计算器。独立双引擎对比工具仍可单独使用。
3. 输入 N 后点击计算，每个战斗房间恰好完成 N 场；成功、死亡和超时都算一场。进度按完成场数 / N 更新，取消会终止当前 Worker。

WASM 已压缩内嵌并校验 SHA-256，计算期间无引擎下载。普通计算的一次 Worker 调用、一次 WASM 调用完成 N 场；推荐每批调用只完成缺少的场数。连续批次复用已解析数据和引擎实例；取消后下次运行重新初始化 Worker，已提交的推荐样本仍可复用。保留 LZString `@require` 读取游戏数据。安装脚本移除原 GreasyFork 更新地址，升级时重新导入。

## 战斗和统计口径

每局立即开始下一局，不增加刷新或复活等待。玩家满血满蓝、临时增益与控制状态清除、冷却重置；怪物重新生成并固定半冷却。升级、怒气修正、普攻间隔和施法时间保留原规则。每批 WASM 调用开始时设种子，同一批次内局间持续推进随机序列；推荐的不同批次各自使用可复现的新种子。

每局严格截止于开始后 **120 秒**。本局时间戳 ≤120 秒的事件按原队列顺序处理，含恰好 120 秒新排入的同时间事件；恰好 120 秒击杀仍算成功。更晚的攻击、施法、DOT、恢复等事件全部不执行、不消耗它们的随机数。处理完截止时刻内的事件仍未分胜负时，直接在 120 秒记超时，再立即开始下一局（已达 N 则停止）。时间判断沿用事件队列现有的微秒精度。

**预计通关时间 = 全部已完成对局的耗时 ÷ 成功通关次数**。计入成功、死亡和超时耗时；零成功为 ∞；第 N 场完整结束后停止，不开启第 N+1 场。普通计算、推荐、拟合、表格、图表及缓存共享此口径。缓存签名为 `rust-completed-battles-v6-progressive-<WASM SHA-256>`，隔离旧采样方式及旧时间模式结果。

`trials` / `completedTrials` 均为真实完成场数。同归于尽只算成功，不再计入死亡失败。`successes + failedByDeath + failedByTimeout = completedTrials`，胜率为 `successes / completedTrials`。`statisticalTrials` 保留为完成场数的等值字段；`terminalDeaths` / `terminalTimeouts` 分别与死亡失败数、超时数相同。

结果的 `combatMeta` 包含以下耗时统计字段；普通计算表示本次 N 场结果，推荐表示当前配置的累计结果：

| 字段 | 单位与含义 |
|---|---|
| `totalSpentSeconds` | 秒，全部完成对局耗时之和；批内 Kahan 累计，批间求和 |
| `durationSquaredSeconds` | 秒²，逐场耗时平方和；批内 Kahan 累计，批间求和 |
| `successSpentSeconds` | 秒，仅成功对局的耗时总和；批内 Kahan 累计，批间求和 |
| `durationMeanSeconds` | 秒，逐场平均耗时 |
| `durationM2SecondsSquared` | 秒²，Welford 在线中心平方和；样本方差为 M2/(N−1) |
| `durationSuccessComomentSeconds` | 秒，耗时与成功指示值的在线中心积和；样本协方差为该值/(N−1) |

所有单场耗时不超过 120 秒；每场超时在总耗时中加 120 秒、平方和中加 14400 秒²，成功耗时总和不计超时。

统计对象为真实完成的每一局，成功指示取 0/1；同归于尽按现有局末成功优先规则记成功。原生 `labyrinthStats.completedSpentNs` 单位为纳秒，其余新增原生字段与 JS 同名、单位相同。这些统计量用于新增的通关耗时近似 95% 区间（Fieller；全胜时使用120秒有界均值与成功率的保守联合界）；原有胜率 Wilson 图保留。

`firstRunDebug` 包含固定引擎标记、实际 WASM 哈希、种子、计算毫秒数、请求/完成场数及模拟时间（纳秒），不再包含总模拟时间预算或回放探针；`battleDurationLimitSeconds=120`、`timeoutMode="strict"` 标明本局截止规则。全局时钟核对与限制见 [源码核对记录](../docs/completed-battles-audit.md)。

## 战斗自动化等级推荐

面板参考 Greasyfork 1.6.0 分行排列：战斗次数与计算胜率、目标胜率与按胜率推荐、目标耗时与按耗时推荐。目标耗时默认 300 秒，范围 1～100000 秒，自动保存在本地。耗时包含失败场次；两个推荐目标各自运行，推荐结果与图表记录本次使用的目标。

内置 Rust 计算器的战斗推荐使用加权单调回归（PAVA），在同一怪物、配装和增益条件下约束拟合胜率随房间等级不升高。每个等级按累计完成场数 `combatMeta.trials` 加权。该拟合用于抑制抽样波动，不代表置信区间，也不能保证真实战斗曲线严格单调。

目标默认 70%，仍可在界面修改。先在基准等级差 −300～+300 内向外探测，再根据拟合曲线插值寻找目标附近的整数等级。选择未四舍五入的拟合胜率最接近目标的已模拟等级，允许低于目标；偏差相同时选更高等级。长平台采用受限插值，避免逐级扫描。生活房间仍使用原推荐算法。

粗搜索累计完成 300 场，在候选及其附近 ±2 级分阶段补足到 1000、3000，并在每轮拟合后重新定位，避免被粗采样的错误边界锁定。300 → 1000 → 3000 是累计场数，依次新增 300、700、2000 场；直接请求更高档时也只补缺少的场数。最终入选等级至少有 3000 场样本。

| 累计目标 | 已有样本 | 本批新增 | 进度范围 |
|---|---|---|---|
| 300 场 | 0 场 | 300 场 | 0/300 → 300/300 |
| 1000 场 | 300 场 | 700 场 | 300/1000 → 1000/1000 |
| 3000 场 | 1000 场 | 2000 场 | 1000/3000 → 3000/3000 |

样本在当前页面内按等级、怪物、完整玩家战斗 DTO、箱子、配置签名和引擎版本保存，胜率/耗时推荐及重复推荐共享样本；改变推荐目标不会使相同配置的样本失效。配置变化后使用对应配置的独立样本。缓存仅在内存中保存，刷新页面后清空；普通计算使用独立的固定场数缓存，不混入推荐样本。已有更多场数时直接返回完整累计结果，不截取旧样本；例如已有 3000 场，再请求 300 场会直接返回 3000 场结果及 3000/3000 进度。

每批复用现有 Worker/WASM，以配置和已完成场数派生不同的可复现种子独立运行；无需恢复模拟器状态，批次内部 RNG 持续推进。计数、总耗时、平方和与成功耗时相加；中心平方和与耗时/成功中心积和用 Chan/Welford 并行公式加入批次均值差修正，再重新计算胜率、预计通关耗时和区间。拟合权重、进度、缓存和调试场数均为累计口径，不直接平均各批胜率、通关耗时比值或置信区间。

仅在批次完整成功且统计有效后提交；失败或取消的批次丢弃，已完成批次保留，重试只补剩余场数，不计入迟到的取消结果。相同配置、相同批前累计场数会派生相同种子，因此未提交批次可用同一种子重试。同一配置的并发请求串行补样，避免重叠计数。取消只保留已经提交的整批样本；当前批次即使已显示部分进度也不会保留。

推荐结果的 `firstRunDebug.samplingMode` 为 `progressive`，请求/完成场数、计算毫秒数和模拟时间使用累计值；`seed` 保留首批种子。`batches` 中每项记录 `startTrials`（批前累计场数）、`trials`（本批新增）、`cumulativeTrials`（批后累计）、`seed` 和 `elapsedMs`，可用相同配置、批次种子和新增场数逐批复现。`lastEncounterFinishTime` 按累计模拟时间定位最后一次成功；后续无成功批次不改变该时间戳。

表格仍显示可填写到“跳过如果高出等级”的等级差 +1。悬停推荐结果会分别显示拟合胜率和该等级的原始模拟胜率。普通“计算胜率”仍显示原始模拟结果，拟合不修改引擎输出或战斗规则。

按耗时推荐复用同一搜索和 300 → 1000 → 3000 的累计目标，对预计通关耗时按累计完成场数加权做 PAVA，约束拟合耗时随等级不降低。选择未四舍五入的拟合耗时最接近目标的等级，允许略超目标，等距时选更高等级；这与 Greasyfork 将目标时间作为上限的选择规则不同。零通关样本的耗时保留为 ∞；全范围没有有限耗时时返回最低等级并显示 ∞，不视为已经达到目标。

耗时图的纵轴和目标线使用秒，每个等级仅显示累计场数最多的最新结果及拟合曲线，悬停可比较累计原始耗时与拟合结果；显示原始预计通关耗时的近似95%区间（Fieller；全胜使用保守联合界），不使用二项胜率区间代替耗时区间。生活及强化房间直接遍历原公式的整数等级耗时，保留取整造成的变化，按同样的最近目标与平局规则选取，不对公式结果做随机样本拟合。

## 胜率—等级图

完成战斗等级推荐后，点击带 `▥` 图标的推荐设置等级打开对应怪物的图表，也可聚焦该单元格后按回车或空格。散点及记录表中每个等级只有一条记录，取累计场数最多的结果，场数相同时取最新结果。重新推荐复用匹配配置的累计样本并更新图表，刷新页面后清空。

- 紫色、蓝色、粉红色散点分别表示累计 300、1000、3000 场，误差棒显示累计原始胜率的 95% Wilson 二项置信区间。每个等级的累计结果参与单调拟合；青色折线连接最终拟合值，不做可能破坏单调性的平滑处理。
- 黄色横线表示目标胜率，竖线标记推荐房间等级。顶部显示推荐等级、拟合胜率、原始模拟胜率和原始胜率的区间。
- 默认展示推荐等级附近的目标区域。可滚轮缩放、拖动平移或点击图例筛选累计场数；“全部范围”展示完整横轴范围，“目标附近”回到默认视图。
- 悬停或点击散点、使用键盘聚焦散点可查看累计成功数/实际统计次数、累计场数、记录编号和区间。“全部等级记录”表每个等级一条记录，点击行可定位对应散点。Esc、关闭按钮或点击遮罩关闭图表，焦点返回推荐单元格；桌面和窄屏均支持。

区间采用 `p = successes / combatMeta.trials` 和 `n = combatMeta.trials`；使用 `z = 1.959963984540054` 的双侧 95% Wilson score 公式。0% 或 100% 样本不会得到零宽区间。公式来源：[NIST 比例置信区间](https://www.itl.nist.gov/div898/handbook/prc/section2/prc241.htm)。对局仍按独立二项试验近似，因此图中区间不保证覆盖率，也不是拟合曲线的置信带。

### 生产房间图表

普通生产和强化房间也可点击推荐等级打开图表。推荐计算完成时，用相同角色、配装、茶箱和迷宫升级参数，逐级计算整个推荐搜索范围（有效技能等级向下取整后 −300～+300，房间等级最低为 1）。生产推荐仍按原算法选取；绘图不会修改推荐结果。

- 青色曲线和点展示原公式计算的通关概率，点对应整数等级，连线仅用于辅助阅读。没有随机模拟、单调拟合或采样置信区间。
- 默认聚焦推荐等级附近，支持全部范围、缩放、拖动和完整等级表。顶部显示推荐等级、计算胜率、每次操作成功率和操作次数。
- 点选等级可查看操作成功率、双倍进度率、120 秒内操作次数，以及普通生产的单次成功进度和所需进度单位；强化房间显示目标强化等级。
- 普通生产按每次操作获得 0、1、2 进度单位的概率动态规划计算；强化按失败退一级、成功升一级或两级、首次达到 +5 的概率动态规划计算。阶梯变化保留原值，不做平滑或拟合。
- 全部等级数据来自本轮推荐时的状态快照；改换配装或升级后，需要重新计算推荐来更新图表。


## 构建和测试

以下命令从 `labyrinth-clear-rate/` 目录开始执行，依赖安装在 `comparison/`。需要 Node.js 20 或更高版本和 npm；构建使用仓库内已有的 WASM。

```sh
cd comparison
npm ci
npm test
node ../calculator/build.mjs
node ../calculator/tests/browser.mjs
```

计算器构建器只生成内置版安装脚本。修改 Rust 后先按 [引擎说明](../comparison/README.md#开发和验证) 重建 `comparison/assets/mwi_engine.wasm`，再运行上述步骤。浏览器测试使用隔离 Chrome、本地页面和合成角色数据；Chrome 路径、输出目录和对比工具命令见[项目 README](../README.md#开发与验证)。

`npm test` 包含计算器和引擎的 Node 回归，其中构建测试会重新生成内置版安装脚本。累进采样测试覆盖差额场数、配置隔离、确定性种子、稳定中心统计与区间、失败/取消重试、并发防重计和每级单条图表记录；浏览器回归还使用真实 Worker/WASM 重放各批种子，核对累计结果、缓存、进度及取消后样本保留。

原版 1.5.14 基准文件及固定 JS 引擎快照供构建器和独立双引擎工具使用，保留不变。对比工具显式保留旧时间模式和最后成功时刻公式，不改变其比较基准。

源码来源与许可沿用原版 MIT 及 `wow121/mwi-fastsim`，生成脚本保留作者与内联许可声明。

## 预计通关时间区间（1.8.0）

使用新增耗时平方和、成功耗时总和和稳定在线方差/协方差，计算“总耗时 / 成功次数”的近似双侧 95% 区间。混合胜负使用配对 Fieller 方法，全胜使用120秒有界均值与成功率的保守联合界，避免零宽区间。普通战斗悬浮详情、自动化结果、推荐等级详情及战斗耗时图（摘要、误差棒、点详情、记录表）均显示。上界无穷或超出坐标轴时用箭头表示；零成功及样本不足显示无法估计。生活和强化公式不显示模拟区间。

区间只描述原始模拟点估计，不是单次通关的预测区间或拟合置信带；不改变推荐/PAVA 规则。小样本、稀少成功及自适应等级搜索的覆盖率不保证。完整公式、字段和限制见 [区间方法说明](../docs/clear-time-confidence-interval.md)。
