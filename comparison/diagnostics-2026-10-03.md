## 根因与修复

原引擎的 Fury 命中加一层（最多五层），未命中将现有层数减半，并覆盖当前怒气增益。上游 Rust 的增益系统为每个同名增益保存多个候选，采用最强值；其 `fury` 仍使用添加候选操作，故未命中后的较低层增益没有替换先前的较高层命中与伤害增益。

将两边枪的 Fury 同时置零后，固定种子重放的胜率一致；移除穿刺技能并不能消除偏差。由此确认差异来自 Fury 增益更新，而不是怪物数据或显示统计。

0.1.1 的 `makeRustScenario` 启用 `labyrinthLegacyFury`。Rust 仅在迷宫且显式开启此选项时，对 Fury 使用覆盖操作。正常战斗及未开启选项时保留上游机制。原版 1.5.14 文件与原引擎算法未修改。

十种怪物的胜利、死亡、超时、完成次数和胜率全部一致。预计通关耗时最大差异小于 0.00003 秒，属于两个引擎的数值精度差异。

原生 Rust 回归直接验证五层怒气 15% 加成，在连续未命中后降为 7.5%、3.75%，覆盖普攻和技能路径并验证增益到期。WASM 回归使用公开合成配装：旧版本错误地产生 26 胜，原引擎和修正版为 24 胜、27 超时。

重放采用原引擎快照的共同基础表，辅助表采用项目保存的公开数据。这些结论针对本次导出的输入和固定随机序列；未开启固定种子时，独立抽样仍有波动。

## 来源追溯补充

mwi-fastsim README 的致谢指向[新战斗模拟](https://combat.43.167.210.211.sslip.io)，将来源引擎标为 `combat-events-2.3.0`。该站当前公开 [Worker 文件](https://combat.43.167.210.211.sslip.io/assets/worker-C6hz9YNo.js) 中也包含这一版本标识。

该 JavaScript Worker 的 Fury 路径同样调用添加候选操作，同名增益系统选择最强候选。本地直接运行其增益方法，先加 15% 再加 7.5%，实际仍采用 15%。因此确认该错误同时存在于源站当前 JavaScript 和 Rust 移植版；不能将其归因于 Rust 移植过程引入。现有证据不足以判断二者历史上谁先引入错误。当前未找到该站自身的公开源码仓库。
